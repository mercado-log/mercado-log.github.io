Nesse post, vou comentar de forma breve o que é o Docker e o conceito de containers. Esse assunto já tinha despertado minha atenção algumas vezes, mas eu nunca tinha me aprofundado de fato. Isso mudou depois de uma aula introdutória e da recomendação de um amigo sobre um canal no YouTube (pra quem se interessar, o nome é Techworld with Nana).

# ![Docker Logo](/assets/images/docker.png)
De forma simples: um container no Docker é algo próximo de uma virtualização, mas não exatamente igual. A principal diferença é que ele não precisa de um sistema operacional completo rodando por trás. Em vez disso, ele usa o kernel do sistema hospedeiro.

A estrutura de um container se parece muito com um serviço: você configura o ambiente e ele executa aquilo de forma isolada. Um exemplo bem comum é subir um container de banco de dados. Nesse caso, o Docker fornece apenas o essencial — como sistema de arquivos, variáveis de ambiente, rede e processos — pra que o banco funcione corretamente.

No dia a dia, o Docker acaba sendo muito útil justamente por essa versatilidade. Ele facilita o gerenciamento de aplicações como serviços e traz mais agilidade pra subir e testar ambientes.

Dá pra usar tanto em Linux quanto em Windows. Como o Docker conversa nativamente com o kernel Linux, no Windows é necessário usar o WSL2 pra fazer essa ponte.

Nos testes que fiz até agora, uma máquina com 2GB de RAM e 2 CPUs já foi suficiente pra rodar o Docker Engine sem problemas. Ainda não cheguei a testar cenários mais pesados.
